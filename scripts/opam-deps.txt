# Pinned opam packages for the Hardcaml generator and its tests (OCaml 5.2.1).
#
# Generator. Every line that does not start with '#' is passed to
# `opam install` by the workflows that build the generator (regen.yaml,
# formal.yaml, certs.yaml, gds_6x4.yaml), which also key their opam cache on
# this file; opam resolves the transitive closure. The generator's only direct
# libraries (hardcaml/lib, hardcaml/bin) are hardcaml, yojson and digestif, and
# it uses no ppx. The committed RTL was produced by a switch that also had
# (among 81 packages) base v0.17.3, core v0.17.2, ppxlib 0.35.0, zarith 1.14
# and ppx_jane v0.17.0; pin those here if a CI regeneration ever diverges from
# a local one.

hardcaml.v0.17.0
yojson.2.2.2
digestif.1.3.1
#
# Tests only. Lines starting with '#test ' are the extra packages for
# hardcaml/test (the waveform expect tests in hardcaml/test/expect). Only the
# "Hardcaml tests" step of regen.yaml installs them, together with the list
# above:
#   opam install $(grep -v '^#' scripts/opam-deps.txt) $(sed -n 's/^#test //p' scripts/opam-deps.txt)
# They are kept out of the list above so that the other workflows install only
# the generator's packages. The versions are the v0.17 releases that the
# generator's pins already resolve to (ppx_jane, ppx_expect and
# base_quickcheck are in hardcaml v0.17.0's dependency closure), so adding
# them changes none of the generator's packages. hardcaml_waveterm also pulls
# in core_unix, async, notty and cryptokit (which needs zlib).
